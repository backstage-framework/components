# Фильтры данных справочников

Строковый фильтр в `DictDataService` разбирается отдельным `QueryParser`, затем переводится в запрос нужного backend. Это выражение условия, без `SELECT`, `WHERE`, `ORDER BY` и завершающего `;`. Пагинация, сортировка и выбираемые поля передаются отдельными параметрами API.

## Выражения

| Назначение | Форма |
| --- | --- |
| Сравнение | `age >= 18`, `name = 'Иван'`, `active != false`; операторы `=`, `!=`, `<>`, `<`, `>`, `<=`, `>=` |
| Проверка null | `name is null`, `name is not null` |
| Набор значений | `status in ('NEW', 'DONE')` |
| Шаблон | `name like 'Ив%'`, `name ilike '%ив%'` |
| Множественное поле | `tags any ['a', 'b']`, `tags all ['a', 'b']` |
| Логика | `age >= 18 and (active = true or status = 'NEW')` |
| Сравнение с отрицанием | `active != true` |
| Тип даты | `created >= '2026-01-01'::date`, `updated < '2026-02-01T12:00:00'::timestamp` |

`AND` имеет приоритет перед `OR`. Скобки задают группировку, а регистр ключевых слов свободный. Для логического `NOT` действуют ограничения ниже.

Константы: числа, строки, boolean, `null`. Поддерживаются строковые литералы в одинарных/двойных кавычках. Cast константы поддерживает только имена `date`, `timestamp` в нижнем регистре; они преобразуются в `LocalDate`/`LocalDateTime`. Не предполагай сохранение часового пояса как `OffsetDateTime`.

Правая часть обычного сравнения — константа, а не другое поле: `field1 = field2` не является допустимым фильтром. Поле может иметь форму `field` или `dict.field`; семантику участия связанных справочников и права проверяй по схеме и backend. Это не произвольный SQL JOIN и не произвольный JSONPath.

`null` или пустая строка фильтра разбираются как пустое условие. Для массовой операции это может означать весь справочник: проверяй область изменения.

## Backend и API

- PostgreSQL использует `PostgresTranslator`, MongoDB — `MongoTranslator`. Общая грамматика не гарантирует одинаковую поддержку всех выражений.
- Парсер принимает логический `NOT`, но текущие MongoDB и PostgreSQL переводчики обрабатывают его как бинарное выражение и обращаются к отсутствующему правому операнду. Используй поддерживаемые сравнения и проверяй результат на нужном backend. Замена `NOT` на `!=` может изменить семантику при `null` и массивах.
- `LIKE`/`ILIKE` переводятся backend; не передавай произвольное регулярное выражение вместо SQL-подобного шаблона.
- `getByFilter` принимает `selectFields`, фильтр и `Pageable`; `streamByFilter` возвращает поток. Не включай сортировку/пагинацию в строку условия.
- Проверки прав действуют и для участвующих связанных справочников. Изменение набора полей может затронуть требования к правам.
