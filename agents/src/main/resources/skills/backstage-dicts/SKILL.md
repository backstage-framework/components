# Справочники Backstage

Работай с API и диалектами подключённой версии Backstage. Сначала определи, есть ли в приложении локальный `DictService` или используются удалённые сервисы `dicts-api`, и какой engine хранит данные нужного справочника.

## Существенные правила

- Изменяй справочники и данные через сервисы Backstage: они обеспечивают проверки прав, валидацию, optimistic locking, историю, кеши и advice. Для обновления записи используй её актуальную `version`.
- Миграции `dicts` исполняются собственными `SqlParser` и `Interpreter`. Используй поддерживаемый DSL, сверяя синтаксис отдельно от возможностей backend.
- Добавляй новые миграции; опубликованные или применённые файлы сохраняй неизменными. До запуска приложения с новой миграцией учитывай, что она применяется при инициализации контекста.
- Фильтры разбирает отдельный `QueryParser`. Проверяй исполнение на нужном backend, особенно для логического `NOT`.
- Расширяй сгенерированные сервисы через существующие advice/base-классы. Запуск `dictsCodegen` поднимает контекст приложения и может применить миграции.

В справочниках указаны исходные классы и тесты репозитория компонентов. Если нужный контракт отличается от описания, проверь sources JAR именно подключённой версии и адаптируй решение к нему.
