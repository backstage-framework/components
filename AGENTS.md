# Инструкции для работы с Backstage Components

## Назначение репозитория

Это многомодульный Java-проект с переиспользуемыми серверными компонентами Backstage. Модули публикуются в Maven-репозиторий с группой `com.backstage` и общей версией `appVersion`. Это библиотеки для приложений-потребителей: исполняемые `bootJar` у серверных модулей отключены.

Перед изменениями прочитай [CODEMAP.md](CODEMAP.md), затем `build.gradle` затрагиваемого модуля и ближайшие существующие реализации и тесты. Карта содержит известные точки входа, зависимости, настройки и инфраструктуру тестов; конкретное поведение проверяй по исходникам.

## Сборка и версии

- Используй Gradle wrapper `./gradlew`; настройки версий находятся в `gradle.properties`, версия wrapper — также в `gradle/wrapper/gradle-wrapper.properties`.
- Java toolchain серверных модулей — 21, кодировка — UTF-8. Основной стек: Spring Boot, Jakarta, EclipseLink, Flyway, jOOQ, Lombok; точные версии смотри в свойствах сборки.
- `gradle-plugins` подключён через `includeBuild`, это отдельная сборка Groovy-плагинов, а не обычный Java-подпроект.
- Корневой `build.gradle` задаёт общие плагины, Java toolchain и Maven-публикации. `dependencies` публикует version catalog и имеет собственную настройку публикации.
- Публикация использует свойства `backstageNexusUrl`, `backstageNexusToken`, `backstageNexusDeployToken`. Не копируй значения токенов в документацию, примеры, сообщения и новые файлы.
- Не запускай `publish` и `updateDependencyVersions` для обычной проверки кода: они публикуют артефакты или изменяют версии зависимостей.

## Стиль и изменения

- Соблюдай стиль соседнего кода: табуляция, фигурные скобки классов и методов с новой строки, пустые строки между смысловыми блоками, `;` в Java. В Gradle DSL сохраняй оформление существующих блоков.
- Используй существующие соглашения о пакетах, Lombok, конструкторах, аннотациях и именах. Java-код расположен преимущественно под `com.backstage.app`, BPM — под `com.backstage.bpm`, Feign — под `com.backstage.feign`, плагины — под `com.backstage.gradle`.
- Сохраняй текущие изменения пользователя; не обновляй wrapper, версии библиотек и несвязанный код в рамках локальной задачи.
- Публичные DTO, интерфейсы сервисов, свойства `app.*`, endpoint-контракты и опубликованные Gradle plugin IDs используются другими приложениями. При изменениях проверяй совместимость и потребителей в соседних модулях.
- Различай зависимости `api` и `compileOnly`: опциональная интеграция не должна незаметно становиться обязательной транзитивной зависимостью.
- В текущем коде уже используется Jackson 3 (`tools.jackson.*`) наряду с аннотациями `com.fasterxml.jackson.annotation`; ориентируйся на импорты конкретного файла.
- Не редактируй результаты генерации в `build/`, JPA metamodel и сгенерированный `persistence.xml`. Меняй исходники или генератор. Генерируемые классы справочников расширяй через предусмотренные advice/base-классы.

## Архитектурные соглашения

- `app` предоставляет общие модели, исключения, безопасность, конвертеры и утилиты; `api` — HTTP/API-инфраструктуру.
- `AppPackage` зарегистрирован через `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports` и сканирует `com.backstage`. Новую интеграцию сверяй с существующими `@Configuration`, `@ConfigurationProperties` и условиями активации.
- JPA работает через EclipseLink и собственную фабрику репозиториев. Плагины генерируют persistence XML, выполняют static weaving и настраивают metamodel; Hibernate metamodel processor не означает, что runtime-провайдер — Hibernate.
- Изменения схемы БД оформляются новыми версионными миграциями в `src/main/resources/db/migration/<component>/`. Существующие выпущенные миграции не переписывай.
- DDL компонентов выполняется через `DDLProvider`, `AbstractDDLProvider`, `DDLProviderInitializer`; учитывай порядок `DDL_PRECEDENCE_SYSTEM` и `DDL_PRECEDENCE_APP`.
- В `dicts` отделены публичный API, сервисы, backend-интерфейсы и реализации PostgreSQL/MongoDB. При изменении общей семантики проверь оба backend и соответствующие наборы тестов.
- Для вложений, аудита, отчётов, заданий, BPM и кеша сначала используй существующие сервисы и расширения, чтобы сохранить проверки прав, транзакции, привязки и обработку событий.

## Проверки

Запускай проверки по области изменения; интеграционные тесты многих модулей требуют работающий Docker и Testcontainers.

```sh
# Артефакт документации для приложений-потребителей
./gradlew :agents:jar

# Отдельная сборка Gradle-плагинов: функциональные тесты и проверка plugin metadata
./gradlew -p gradle-plugins test validatePlugins

# Тесты конкретного серверного модуля / класса
./gradlew :app:test
./gradlew :dicts:test --tests '*PostgresDictServiceTest'

# Checkstyle затронутого Java-модуля
./gradlew :app:checkstyleMain

# Полная проверка, если нужна проверка всех модулей и доступна инфраструктура
./gradlew check
```

`backstage-checkstyle` использует Checkstyle 10.25.0 и отдельный артефакт правил `com.backstage:checkstyle`. При конфигурации сборки плагин создаёт/обновляет `.git/hooks/pre-commit`; учитывай этот побочный эффект при запуске Gradle в ограниченном окружении. `checkstyleApplyConfig` извлекает настройки, а `-PsourceFiles=...` позволяет передавать конкретные файлы для проверки.

Если проверка не прошла из-за недоступного Maven-репозитория, Docker или внешнего сервиса, укажи фактическую причину и какие проверки удалось выполнить. Не представляй такую проверку как успешную.

## Документация для агентов

- `agents` публикует отдельный JAR `com.backstage:agents:<appVersion>` без runtime-зависимостей. Он содержит инструкции для приложений-потребителей из `agents/src/main/resources/` и корневой `CODEMAP.md`.
- Плагин `backstage-agent-docs` устанавливает документацию при конфигурации приложения, после обработки его `build.gradle`. Достаточно применить плагин и перезагрузить Gradle-проект в IDE; отдельной задачи `syncAgentDocs` нет.
- Версия базового артефакта документации определяется через `agentDocs.version`, затем свойство `backstageVersion`, затем версию Backstage, встроенную в `gradle-plugins`.
- Для обновления документации вместе с компонентами используй общее `backstageVersion` для библиотек и плагинов, не фиксируя отдельно `agentDocs.version`. При смене версии следующий импорт/запуск Gradle загружает соответствующий артефакт.
- По умолчанию документация извлекается в корневой `.agents/backstage`, включая применение плагина в подпроекте. Каталог находится вне `build` и сохраняется после `clean`. Плагин управляет его содержимым, удаляет прежние управляемые копии в `.gradle/backstage/agent-docs` и добавляет `/.agents/` в существующий корневой `.gitignore` при отсутствии правила. Для переопределения выбирай отдельный `outputDirectory`, выделенный под документацию.
- Явная зависимость в конфигурации `agentDocs` заменяет зависимость по умолчанию; это должен быть опубликованный артефакт или уже собранный JAR, доступный на фазе конфигурации. В самом `components` плагин не применяется, локальной зависимости `agentDocs project(':agents')` нет.
- Корневой `AGENTS.md` предназначен для разработки компонентов и не включается в потребительский JAR. Плагин обновляет отдельный блок Backstage в корневом `AGENTS.md` потребителя со ссылкой на базовый `README.md` или общий `LIBRARIES.md` при наличии материалов из библиотек.
- Библиотеки могут поставлять документацию в ресурсах `META-INF/backstage/agents/`, включая `skills/<имя>/SKILL.md`. Плагин берёт опубликованные JAR из основного `runtimeClasspath` проекта приложения, включая транзитивные зависимости. Пакет извлекается в `<group>/<artifact>/` внутри выходного каталога. Версия материалов соответствует выбранному JAR.
- Основные документы пакета называются `README.md`, `COMPONENTS.md`, `CODEMAP.md`; справочники внутри skills — lowercase-kebab-case. `skills/backstage-dicts/SKILL.md` содержит маршрутизацию к справочникам по возможностям, конфигурации, миграциям и фильтрам; cookbook пока не поставляется.
- Плагин устанавливает каждый skill только в корневой `.agents/skills` и пересчитывает ссылки между документацией и skills. Обновляются только каталоги со своим маркером `.backstage-agent-docs`. Дубли между источниками и конфликты с неуправляемыми каталогами проверяются до записи. `AGENTS.md` направляет к нужному skill или модулю.
- Блок Backstage ограничен HTML-маркерами; остальной текст `AGENTS.md` сохраняется. При смене выходного каталога ссылка обновляется. Повреждённые или повторяющиеся маркеры требуют исправления: плагин завершает конфигурацию ошибкой, сохраняя файл. Установленные файлы учитываются при проверке configuration cache.
- При изменении архитектуры обновляй `CODEMAP.md`, при изменении интеграции компонентов — также `agents/src/main/resources/COMPONENTS.md`. Общие правила разработки поддерживай в этом файле.
